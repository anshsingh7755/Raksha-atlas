# Data documentation

## What is data documentation?

These guides explain how project information is shaped, labelled, checked and displayed. They are important because the website combines information from different publishers and different dates.

## Documents

- [Inventory classification and reconciliation](INVENTORY-CLASSIFICATION-AND-RECONCILIATION.md) — field definitions, evidence quality, source attribution and checks for copied data.
- [Programme timeline and information architecture](PROGRAMME-TIMELINE-AND-INFORMATION-ARCHITECTURE.md) — how programmes, milestones, dates and timeline entries should be represented.
- [Inventory guide](../inventory/INVENTORY-DATA.md) — current inventory and procurement source files.

## Rules that apply to all data

1. Keep the original source URL and publisher.
2. Keep publication date and the date the project collected or updated the record.
3. Preserve the source's wording when a quantity is a range or estimate.
4. Keep proposals, approvals, tenders, contracts, deliveries and inductions as separate stages.
5. Do not label a claim verified only because the publisher is official.
6. Record missing or uncertain information instead of guessing.
7. Reconcile imported records before changing the application's source of truth.
